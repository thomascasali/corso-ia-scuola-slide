Guida: OpenCode sul PC del laboratorio, collegato al server del corso

Questa guida porta OpenCode, un agente di programmazione, dall'installazione alla prima richiesta, sul PC del laboratorio. Si usa OpenCode desktop, l'applicazione per Windows con le sue finestre. In fondo, come alternativa, c'è la versione da terminale. OpenCode non parla con un fornitore esterno: parla con il server del corso, che ha già tutto configurato e che vi ha dato una chiave personale.

Due segnaposto, che trovate sul foglio consegnato in aula:

  • <indirizzo del server>: l'indirizzo del server del corso, nella forma http://...:4000;
  • <la tua chiave>: la vostra chiave personale, che comincia con sk-.

Cosa serve

  • Un PC Windows 10 o 11 con PowerShell (è già installato).
  • Il foglio con indirizzo e chiave.
  • Un collegamento a internet, per scaricare l'installatore. Il server del corso si raggiunge dalla rete del laboratorio.

L'app si installa solo per il vostro utente: non servono i permessi di amministratore. Se Windows chiede la password di amministratore o blocca l'installatore, fermatevi e chiamate il docente (da verificare a schermo sui PC del laboratorio).

1. Installare OpenCode desktop

  1. Aprite la pagina di download di opencode.ai (indirizzo: opencode.ai/download).
  2. Nel riquadro dell'app desktop scegliete la voce Windows (x64). Si scarica un file opencode-desktop-win-x64.exe. Se il PC avesse un processore ARM, c'è la voce Windows (ARM64).
  3. Aprite il file scaricato e seguite l'installazione fino alla fine. I passaggi della finestra di installazione non sono stati verificati: da verificare a schermo.
  4. Se Windows mostra un avviso di protezione, fermatevi e chiamate il docente. Sui PC del laboratorio questo passaggio non è ancora stato provato.
  5. Non aprite ancora OpenCode. Prima servono la chiave e il file di configurazione: l'app li legge all'avvio.

L'app installa i suoi file nel vostro profilo utente (di solito in %LOCALAPPDATA%\Programs), per questo non servono permessi speciali. Lavora con un servizio che resta attivo in secondo piano: è il motivo del passaggio 4.

2. La chiave

La chiave è una password: non va scritta nei file di un progetto. La mettiamo in una variabile d'ambiente dell'utente, che OpenCode leggerà all'avvio.

  1. Menu Start, scrivete variabili e scegliete la voce che finisce con relative all'account (per esempio "Modifica le variabili di ambiente relative all'account"). Non scegliete quella "di sistema": chiede l'amministratore.
  2. Nella lista in alto (variabili utente) premete Nuova.
  3. Nome: CORSO_API_KEY. Valore: incollate <la tua chiave> dal foglio. Confermate con OK su tutte le finestre.

Se la finestra delle variabili non si apre sul PC del laboratorio, chiamate il docente: con l'app desktop la variabile deve essere una variabile utente, non basta scriverla in una finestra di PowerShell.

Per controllare senza mostrare la chiave, aprite PowerShell (una finestra nuova, aperta dopo aver creato la variabile):

if ($env:CORSO_API_KEY) { "chiave presente" } else { "chiave mancante" }

3. Il file di configurazione

Il file si chiama opencode.json e sta nella cartella di configurazione personale di OpenCode. Si crea così, in PowerShell, un comando alla volta:

New-Item -ItemType Directory -Force "$env:USERPROFILE\.config\opencode" | Out-Null

notepad "$env:USERPROFILE\.config\opencode\opencode.json"

Se Blocco note chiede se creare il file, rispondete di sì. Incollate questo testo, sostituendo <indirizzo del server> con quello del foglio. Lasciate in fondo all'indirizzo il pezzo /v1, e non scrivete la chiave: c'è già {env:CORSO_API_KEY}, che legge la variabile.

{
  "$schema": "https://opencode.ai/config.json",
  "share": "disabled",
  "autoupdate": false,
  "enabled_providers": ["corso"],
  "provider": {
    "corso": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Server del corso",
      "options": {
        "baseURL": "<indirizzo del server>/v1",
        "apiKey": "{env:CORSO_API_KEY}"
      },
      "models": {
        "claude-haiku-5-5": { "name": "Haiku (veloce)" },
        "claude-sonnet-5-5": { "name": "Sonnet (più capace)" }
      }
    }
  },
  "model": "corso/claude-haiku-5-5"
}

Salvate con Ctrl+S. Un esempio dell'indirizzo, con valori inventati: http://192.0.2.10:4000/v1.

Cosa dice, riga per riga:

Riga Significato
"share": "disabled" Impedisce di pubblicare una conversazione su un sito esterno.
"autoupdate": false OpenCode non si aggiorna da solo: resta la versione provata.
"enabled_providers": ["corso"] Mostra solo il server del corso. Senza questa riga OpenCode propone anche modelli gratuiti di altri servizi, e mandare lì i vostri testi non è quello che vogliamo.
"npm": "@ai-sdk/openai-compatible" Il server del corso parla un linguaggio molto diffuso (quello di OpenAI): questo componente lo conosce.
"baseURL" L'indirizzo del server, con /v1 in fondo.
"apiKey": "{env:CORSO_API_KEY}" Legge la chiave dalla variabile creata prima. Se la variabile non c'è, la chiave resta vuota e il server rifiuta le richieste.
"models" I modelli che potete usare. I nomi devono essere identici a quelli del server.
"model" Il modello con cui OpenCode parte.

4. Chiudere tutto e riaprire

Questo passaggio è quello che più spesso fa perdere tempo. L'app desktop lascia un servizio attivo in secondo piano, e quel servizio non vede una variabile creata dopo la sua partenza. Se resta acceso, OpenCode risponde con un errore sulla chiave anche se la chiave è giusta.

  1. Se OpenCode è aperto, chiudetelo dalla sua finestra.
  2. Fermate i processi rimasti, in PowerShell:
Get-Process opencode* -ErrorAction SilentlyContinue | Stop-Process -Force

Se non scrive niente, non c'erano processi aperti: va bene.

  1. Aprite di nuovo OpenCode dal menu Start. Ora legge la variabile e il file di configurazione.

Se in laboratorio la variabile non viene vista nemmeno così, uscite da Windows e rientrate con il vostro utente (da verificare a schermo), poi riaprite OpenCode.

5. Aprire una cartella di lavoro e fare la prima prova

OpenCode lavora dentro una cartella: ciò che l'agente legge, crea e modifica sta lì. Create una cartella di prova, in PowerShell:

New-Item -ItemType Directory -Force "$env:USERPROFILE\prova-opencode" | Out-Null

Poi, dall'app, aprite quella cartella come progetto. Il nome del pulsante o della voce di menu per aprire una cartella è da verificare a schermo: cercate qualcosa come "Apri progetto" o "Open project" e scegliete prova-opencode dentro il vostro profilo utente.

Nella finestra di scrittura dell'app provate due richieste, una alla volta. La prima è una risposta di testo:

Rispondi con una frase: come ti chiami e che modello sei?

La seconda è un compito con gli strumenti:

Crea un file ciao.txt con scritto: Ciao dal laboratorio. Poi leggilo e dimmi cosa contiene.

Nel secondo caso vedrete comparire le azioni dell'agente (scrittura e lettura del file). Se l'app chiede un permesso, leggetelo e rispondete sì solo se è quello che vi aspettate. Alla fine il file ciao.txt è nella cartella di prova: lo vedete in Esplora file. È la differenza tra un chatbot e un agente: il chatbot risponde, l'agente fa delle cose sul vostro computer, qui dentro la cartella in cui lo avete aperto.

6. Scegliere il modello

Nell'app c'è un selettore del modello vicino alla finestra di scrittura (la posizione esatta è da verificare a schermo). Ne avete due:

  • Haiku: veloce ed economico. Va bene per cominciare e per i compiti semplici.
  • Sonnet: più capace, più lento, costa di più. Usatelo quando Haiku sbaglia o il compito è articolato.

Regola pratica: partite da Haiku e passate a Sonnet solo se serve. Il modello con cui OpenCode parte è quello scritto nel campo "model" del file.

Per controllare che OpenCode legga il file e veda i due modelli, senza aprire l'app:

& "$env:LOCALAPPDATA\Programs\@opencodedesktop\resources\opencode-cli.exe" models

Dovrebbe elencare due righe: corso/claude-haiku-5-5 e corso/claude-sonnet-5-5. Se ne vedete altre, enabled_providers non è stato letto: ricontrollate il file (virgole, virgolette, parentesi). Il percorso del programma è quello dell'installazione per utente; se il comando dice che non trova il file, la cartella ha un altro nome sul vostro PC (da verificare a schermo).

7. Quanto costa

La vostra chiave ha un budget. Ogni richiesta ne consuma un po': le richieste lunghe o con molti file ne consumano di più, e Sonnet più di Haiku. Quando il budget finisce, il server rifiuta le richieste con un messaggio di errore. Non succede niente di grave: avvisate il docente.

8. Problemi frequenti

1. Authentication Error, No api key passed in.

  • Causa: OpenCode non vede la variabile CORSO_API_KEY. Di solito l'avete creata dopo aver avviato l'app, o il nome è scritto diverso.
  • Cosa fare: controllate con il comando "chiave presente / chiave mancante" della sezione 2 in una finestra PowerShell nuova. Poi rifate il passaggio 4: chiudere l'app, fermare i processi, riaprire.

2. Authentication Error ... Invalid proxy server token passed.

  • Causa: la chiave c'è ma è sbagliata o copiata male: un carattere in meno o in più, uno spazio in fondo, oppure è la chiave di un'altra persona.
  • Cosa fare: ricopiate la chiave dal foglio nella variabile. Per vedere le ultime quattro lettere di quella che OpenCode legge, in una finestra PowerShell nuova:
$env:CORSO_API_KEY.Substring($env:CORSO_API_KEY.Length-4)

Confrontatele con le ultime quattro lettere della chiave sul foglio. Se sono diverse, correggete la variabile e rifate il passaggio 4 (chiudere, fermare i processi, riaprire). Se sono uguali e l'errore resta, chiamate il docente.

3. The requested model '...' is not available for this API key, or the model name is invalid.

  • Causa: avete scelto un modello che la vostra chiave non può usare, oppure il nome nel file non è identico a quello del server.
  • Cosa fare: usate solo i due modelli dell'elenco.

4. OpenCode parte, si scrive il messaggio e non succede niente, senza errori.

  • Causa più probabile: l'indirizzo o la porta del server sono sbagliati, oppure il PC non è nella rete del laboratorio. Nelle prove, una porta sbagliata non produce nessun messaggio: l'agente resta fermo.
  • Cosa fare: ricontrollate baseURL nel file (indirizzo del foglio, :4000, /v1 in fondo). Poi provate da PowerShell il comando qui sotto, dopo aver sostituito <indirizzo del server> con quello del foglio. Se la risposta è un elenco di modelli, il server funziona e il problema è nel file. Se non risponde, avvisate il docente.
curl.exe <indirizzo del server>/v1/models -H "Authorization: Bearer $env:CORSO_API_KEY"

5. Il selettore mostra molti modelli di altri servizi, o nessuno del corso.

  • Causa: il file non è stato letto per intero (errore di sintassi) oppure è nella cartella sbagliata.
  • Cosa fare: il file deve chiamarsi opencode.json (non opencode.json.txt: in Blocco note scegliete "Tutti i file" al salvataggio) e stare in %USERPROFILE%\.config\opencode\. Dopo averlo corretto, rifate il passaggio 4.

6. Unexpected server error. Check server logs... appena dopo aver scelto un modello.

  • Causa: il modello scelto non compare nel file opencode.json.
  • Cosa fare: tornate a Haiku dal selettore dei modelli.

7. Ho cambiato la chiave o il file, ma l'app si comporta come prima.

  • Causa: il servizio in background è rimasto acceso con le impostazioni vecchie.
  • Cosa fare: rifate il passaggio 4, sempre.

9. Cosa non fare

  • Non condividete la chiave: non fotografatela, non scrivetela in chat, non passatela a un compagno. È collegata al vostro nome e al vostro budget. Se pensate che qualcuno l'abbia vista, ditelo al docente: il docente può revocarla e darvene un'altra.
  • Non scrivete la chiave dentro un file di progetto (opencode.json in una cartella di lavoro, AGENTS.md, appunti). Solo nella variabile d'ambiente.
  • Non date all'agente dati personali di studenti, famiglie o colleghi, né documenti riservati. Usate solo materiale inventato o pubblico.
  • Aprite OpenCode solo in cartelle di prova: l'agente può creare, modificare e cancellare file in quella cartella. Non apritelo nella cartella Documenti o sul Desktop.
  • Leggete ogni richiesta di permesso prima di rispondere sì.
  • Alla fine del corso, se il PC è condiviso, rimuovete la variabile CORSO_API_KEY dalle variabili d'ambiente dell'account e disinstallate l'app (Impostazioni di Windows, App installate).

Alternativa: OpenCode da terminale

Se l'app desktop non si installa o non parte, c'è la versione da terminale: un unico file eseguibile, senza installazione. La chiave e il file opencode.json (sezioni 2 e 3) sono gli stessi. Questa strada è provata con la versione 1.19.5.

In PowerShell, un comando alla volta. Il primo nasconde la barra di avanzamento, che rallenta il download:

$ProgressPreference = 'SilentlyContinue'

New-Item -ItemType Directory -Force "$env:USERPROFILE\opencode" | Out-Null

Invoke-WebRequest "https://github.com/anomalyco/opencode/releases/download/v1.19.5/opencode-windows-x64.zip" -OutFile "$env:USERPROFILE\opencode\opencode.zip"

Expand-Archive "$env:USERPROFILE\opencode\opencode.zip" -DestinationPath "$env:USERPROFILE\opencode" -Force

& "$env:USERPROFILE\opencode\opencode.exe" --version

Deve scrivere 1.19.5. Poi, nella cartella di prova:

cd "$env:USERPROFILE\prova-opencode"

& "$env:USERPROFILE\opencode\opencode.exe"

L'interfaccia si apre nella finestra del terminale. Per provare in fretta senza interfaccia:

& "$env:USERPROFILE\opencode\opencode.exe" run "Rispondi solo con la parola: pronto"

Il modello si sceglie con -m, per esempio -m corso/claude-sonnet-5-5. Se Windows blocca il programma, fermatevi e chiamate il docente. Se il PC è molto vecchio e il programma non parte, nella stessa pagina di GitHub c'è il file opencode-windows-x64-baseline.zip: stessa procedura, cambia il nome del file.
